# 187 项科研技能 · 50 张组合脑图精制任务书

## 1. 任务目标

围绕 LL-AcademicSkillsHub 的 **18 个类别、187 项技能**，设计并产出 **50 张技能组合使用脑图**。每张图组合 3–6 项技能，展示一个能够真实执行的科研任务链，而不是把相近技能简单堆在一起。

最终作品必须同时回答四个问题：

1. 这组技能共同解决什么科研问题；
2. 每项技能在流程中承担什么独立责任；
3. 上一项技能交给下一项技能的具体中间产物是什么；
4. 组合后如何形成证据、数据、模型、写作或质量控制闭环。

## 2. 核心设计原则

### 2.1 全覆盖而非只展示热门技能

- 187 项技能至少在 50 张图中各出现一次；
- 检索、证据分析、统计、计算资源、可视化、写作和审计等枢纽技能允许跨图复用；
- 每张图包含 3–6 项技能；
- 每张图至少跨越两个能力层，避免全部节点来自同一类工具；
- 每个组合必须有明确输入、协作链、产出和质量门。

### 2.2 组合逻辑必须可执行

每个组合按以下逻辑建模：

```text
研究输入
  → 数据或证据获取
  → 规范化与质量控制
  → 专业分析或建模
  → 解释与验证
  → 学术交付
  ↺ 审计、复现或反馈回流
```

技能之间的连线必须标明交接对象，例如：

- `检索式与去重文献集`
- `标准化 AnnData`
- `候选分子与描述符矩阵`
- `外部验证性能与误差清单`
- `证据锚点与引用记录`
- `可编辑图稿与投稿版文件`

不使用“辅助”“增强”“赋能”等无法验收的空泛关系词。

### 2.3 图像是专业流程图，不是装饰海报

- 技术制图采用确定性 SVG，确保中文、英文名、箭头和细节准确；
- 同时导出高清 PNG，便于 README、社交媒体和演示文稿使用；
- 所有图片保留可编辑的数据源和生成脚本；
- 视觉语言统一，但 50 张图根据科研领域采用不同的结构和强调层级；
- 不用 AI 位图生成技术文字，避免错字、伪符号和不可编辑内容。

## 3. 单图信息结构

每张图必须包含以下层级：

1. **组合编号与标题**：一句话定义任务；
2. **研究目标**：说明组合解决的真实科研场景；
3. **输入契约**：用户需要提供的数据、问题或材料；
4. **技能节点**：3–6 项，每项显示中文名、英文 ID、独立职责；
5. **有向交接线**：显示技能间的中间产物与依赖关系；
6. **协同增益**：说明组合相比单技能多获得了什么；
7. **质量门**：列出复现、统计、伦理、许可或人工复核要求；
8. **最终产出**：明确文件、数据、模型、证据或决策记录；
9. **所属研究阶段**：发现、设计、实验、分析、写作、传播或治理；
10. **品牌标识**：LL-AcademicSkillsHub / 链邻学术技能仓库。

## 4. 视觉系统

### 4.1 画布与输出

- 主画布：1920 × 1080，16:9；
- 可编辑源文件：SVG；
- 发布文件：PNG，至少 1920 × 1080；
- 预览缩略图：WebP 或 PNG；
- 文本最小字号在 GitHub 100% 宽度显示时仍可辨认；
- 为移动端提供可点击原图链接。

### 4.2 视觉语法

- 深色科研蓝黑底色，配合低对比网格和精确对齐线；
- 不同研究阶段使用固定色彩：发现蓝、实验青、分析紫、验证橙、交付红；
- 技能节点采用统一卡片组件；
- 实线表示数据或证据流，虚线表示校验，回路线表示反馈；
- 节点编号与图例保持一致；
- 只使用有限图标，不让图标替代文字含义；
- 一张图只保留一个视觉中心，避免所有卡片同等抢眼。

### 4.3 可读性门槛

- 标题在 README 缩放视图中可直接阅读；
- 节点说明不超过两行；
- 连线不穿过文字，不出现无法判断方向的交叉；
- 同一张图最多使用 6 个技能节点、3 个辅助信息区；
- 关键流程在 5 秒内可顺序读出；
- 色彩对比满足常见色觉差异下的辨识要求。

## 5. 生产阶段

### 阶段 A：187 项技能知识底图

**工作内容**

- 读取 `catalog/skills.seed.json`、18 个分类和 187 份中文说明；
- 提取每项技能的研究对象、输入、处理、输出、依赖、边界和上下游关系；
- 形成机器可校验的技能关系矩阵；
- 标记枢纽技能、领域技能、交付技能和质量控制技能。

**验收标准**

- 187 个技能 ID 无遗漏、无重复定义；
- 每项技能都有至少一个输入、处理职责和输出；
- 每项技能至少分配到一张组合图；
- 组合依据能够回溯到仓库中的技能说明。

### 阶段 B：50 个组合主题与覆盖审计

**工作内容**

- 按完整科研周期规划 50 个真实场景；
- 每组选择 3–6 项技能；
- 为每条边定义交接产物；
- 建立技能覆盖率、类别覆盖率和重复率报告。

**验收标准**

- 图数恰好为 50；
- 每图技能数为 3–6；
- 187 项技能覆盖率为 100%；
- 每图至少包含一个可交付结果和一个质量门；
- 不存在仅以“同属一类”为理由的组合。

### 阶段 C：视觉母版与首批样图

**工作内容**

- 建立色板、字体、卡片、连接线、图例和页脚系统；
- 选择 3 个复杂度不同的组合制作样图；
- 在桌面宽度和移动端宽度测试；
- 检查中文排版、箭头方向、节点密度和视觉节奏。

**验收标准**

- SVG 在浏览器中无渲染错误；
- PNG 与 SVG 内容一致；
- 关键文字在 README 页面可读；
- 图中不存在截字、重叠、连线歧义和低对比文本；
- 视觉风格与现有链邻品牌一致且明显升级。

### 阶段 D：50 张图分批制作

按每批 5 张推进，共 10 批。每批完成后执行：

1. 内容关系复核；
2. 技能名称和 ID 校验；
3. 交接产物校验；
4. SVG 结构检查；
5. PNG 像素与文本检查；
6. 与前批图的重复度检查。

未通过当前批次门禁，不进入下一批。

### 阶段 E：总览串联与项目集成

**工作内容**

- 创建 50 图总索引；
- 按科研生命周期和学科分支建立导航；
- 创建一张只展示 50 个场景之间关系的总览图；
- 在 README 中提供精选图、完整图库入口和原图链接；
- 为每张图提供对应技能详情链接。

**验收标准**

- 用户可从总览进入任一组合图；
- 用户可从组合图进入相关技能说明；
- 所有相对链接有效；
- README 不因 50 张大图而失去阅读节奏；
- 图片目录、命名和版本信息可维护。

### 阶段 F：全量质量审计

**自动检查**

- 50 张 SVG 和 50 张 PNG 均存在；
- SVG 可解析且包含正确标题和描述；
- 组合配置中的技能 ID 全部存在；
- 单图技能数、总覆盖率和类别分布符合要求；
- 文档链接、图片链接和构建流程通过；
- 仓库原有测试与目录校验通过。

**人工视觉检查**

- 每张图在 100%、67% 和移动端宽度检查；
- 检查视觉中心、阅读顺序、文字密度和专业可信度；
- 检查颜色、留白、线条和卡片间距；
- 检查是否把预测、相关、模拟误写成事实或因果；
- 检查临床、专利、金融和实验自动化场景的风险提示。

```text
    50-skill-combination-maps.zh-CN.md

scripts/
  build_skill_combinations.py        # 确定性制图
  validate_skill_combinations.py     # 覆盖与结构审计
```

## 7. 分批检查点

| 检查点 | 完成范围 | 必须通过 |
|---|---|---|
| C0 | 187 项关系矩阵 | ID、输入、输出、上下游完整 |
| C1 | 50 个组合定义 | 100% 技能覆盖、每图 3–6 项 |
| C2 | 3 张首批样图 | 视觉、可读性、渲染检查 |
| C3 | 第 1–15 张 | 内容审计与跨图一致性 |
| C4 | 第 16–30 张 | 领域逻辑与风险边界 |
| C5 | 第 31–45 张 | 全局重复度与视觉节奏 |
| C6 | 第 46–50 张及总览 | 导航、链接、覆盖率 |
| C7 | 全仓库集成 | 构建、测试、图片和文档全通过 |

## 8. 质量红线

- 不虚构技能能力、数据来源、模型性能或科研结论；
- 不把 3–6 个技能并排列出后称为“组合”；
- 不使用无法准确呈现文字的生成式位图作为技术主图；
- 不为了塞入更多信息牺牲可读性；
- 不遗漏 187 项中的冷门、基础设施或文档工具；
- 不把临床建议、投资分析、专利判断或自动化实验描述为无需人工复核；
- 不只交付图片，必须同时交付数据源、生成脚本、索引和审计结果。

## 9. 完成定义

只有同时满足以下条件，任务才算完成：

- 50 张组合脑图全部完成；
- 187 项技能在组合配置中覆盖率 100%；
- 每图 3–6 项技能，逻辑可执行、交接产物清楚；
- 50 份 SVG、50 份高清 PNG、总览图、索引文档齐全；
- 自动校验、项目构建和测试全部通过；
- 逐图视觉审计无阻断问题；
- README 与文档入口完成集成；
- 最终成果可由下一次对话读取任务书和数据源后继续维护。
