# What If Oracle

[返回技能总览](../../../../README.md) · [English](en.md) · [查看原始 SKILL](../SKILL.md)

## 1. 技能简介

通过多分支可能性探索运行结构化假设场景分析。当用户提出诸如“如果……会怎样”、“如果……会发生什么”、“可能性是什么”、“探索场景”、“场景分析”、“可能性空间”、“可能出错的地方”、“最好情况/最坏情况”、“风险分析”、“应急计划”、“战略选择”或任何有关不确定未来的问题等推测性问题时，请使用此技能。当用户面临岔路口决策、想要对想法进行压力测试或需要在做出决定之前考虑后果时也会触发。

它属于“研究方法与科学思维”类别，核心定位是：把研究问题落实为可检验、可执行、可复现并能识别偏倚的方法方案。本说明把原始技能的技术内容整理为中文使用契约；涉及具体命令、参数或版本时，仍以[原始 `SKILL.md`](../SKILL.md)及随附文件为准。

## 2. 适合用它做什么

- 明确研究问题与假设
- 设计可复现研究流程
- 识别偏倚、限制与核验点
- 当你已有“研究问题、数据条件、方法约束”，并希望得到“研究设计、分析计划或方法评估”时使用。
- 当任务需要围绕“把研究问题落实为可检验、可执行、可复现并能识别偏倚的方法方案”形成可复核、可继续加工的中间产物时使用。

不建议仅因为技能名称相近就直接调用；先确认研究对象、输入格式和预期产出与本页描述一致。

## 3. 工作方式

本技能按“输入契约 → 执行 → 验证 → 交付”工作。原始指令的重点阅读路径为：`核心能力与原则` → `工作流程` → `专题说明` → `模式与参数` → `边界与问题排查` → `参考资料`。

1. **明确研究问题、假设、分析单位与目标效应。** 本技能至少需要：研究问题、数据条件、方法约束。
2. **设计采样、对照、测量、随机化或质性研究程序。** 保留关键选择、参数、筛选条件和中间结果，便于复核。
3. **预先定义排除、缺失、偏倚控制和判定规则。** 执行重点包括：明确研究问题与假设；设计可复现研究流程；识别偏倚、限制与核验点。
4. **形成协议、分析计划、风险清单与复现记录。** 最终交付：研究设计、分析计划或方法评估。
5. **交付前复核。** 检查结果是否回答原始问题，是否区分事实、推断和不确定性，是否留下足够的复现与交接信息。

## 4. 请求说明

你可以直接用自然语言提出任务。一个高质量请求最好同时写清目标、输入、约束、产出格式和验收标准。

### 推荐请求模板

> 请使用“What If Oracle”处理【研究问题、数据条件、方法约束】。目标是【写明研究目标】；请遵守【时间范围、对象范围、格式或方法约束】，输出【研究设计、分析计划或方法评估】，并列出关键步骤、证据来源、不确定性和需要人工确认的事项。

### 可直接改写的请求

- “请用 What If Oracle 完成明确研究问题与假设。我的材料是【研究问题、数据条件、方法约束】，结果请整理为【研究设计、分析计划或方法评估】。”
- “请先检查我提供的【研究问题、数据条件、方法约束】是否足够，再用 What If Oracle 执行识别偏倚、限制与核验点；不要补造缺失信息。”
- “请把 What If Oracle 的处理过程做成可复核记录，交付【研究设计、分析计划或方法评估】，同时标出假设、限制和下一步建议。”

## 6. 你需要提供

- **必需输入：**研究问题、数据条件、方法约束。
- **任务目标：**要回答的问题、使用场景和完成标准。
- **范围限制：**研究对象、时间范围、排除条件、语言、格式或目标期刊等。
- **已有材料：**原始数据、文献、代码、图表、协议或草稿；请说明版本及允许使用的范围。
- **交付偏好：**文件格式、字段结构、是否需要脚本、是否保留中间结果与审计记录。

如果上述信息不全，应先列出缺口并向用户确认；不能把猜测当作用户已提供的事实。

## 9. 边界

- 方法建议不能替代伦理审批、临床判断和法定合规程序。
- 不能在看到结果后静默改写假设、终点或排除规则。
- 样本量与效应判断需要领域参数，缺失时必须明确不确定性。
- 本技能的职责是“把研究问题落实为可检验、可执行、可复现并能识别偏倚的方法方案”，不能替代与任务相关的伦理、临床、法律、安全或领域专家审查。
- 外部数据、接口和模型的内容可能变化；重要结论应保存来源、访问时间和稳定标识。
